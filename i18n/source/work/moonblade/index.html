An AI interface for a physical object.

A classmate’s drone assembly at summer camp raised a larger question: how could AI obtain reliable information about the particular device someone was working with?

Moonblade · Static Object Context Interface

Read the historical Runtime trace

Where the question began

A classmate attended a summer camp where assembling a drone meant looking up tutorials and learning the hardware basics. That experience raised a problem for me: AI could answer many technical questions, yet it would struggle to obtain reliable background context for a particular device. Could a physical object have an interface for AI?

Step-by-step guidance might offer less than a manufacturer’s existing video or manual. The design question shifted toward the information AI would need before giving guidance: which object and version it was dealing with, where a claim came from, and whether that information still applied.

The current focus

The active product is a static Object Context Interface with local tools for preparing, checking, and handing over information about a particular object. It brings together sources, applicable models and versions, unknowns, and conflicting claims so AI or another program can read the context for a specific task. When information changes, the tools help inspect which context is affected.

For example, when a device manual changes, a developer needs to know which version the new information covers, which claims have sources, and which existing context needs another look. This is the kind of handoff the interface is designed to support.

The interface has local checks and is awaiting external use and maintenance feedback. It has not been publicly released.

In earlier Runtime work, I explored task conditions, conflicting evidence, and recovery. The eight-input replay preserves one synthetic software experiment from that work; the Runtime and hardware experiments are now archived.

Keep disagreement in the record

The important choice is visible between inputs 3 and 7: a new observation does not simply replace the previous one. The Runtime records the contradiction, retains the earlier value while conflicted, and waits for its recovery conditions to be satisfied.

Keeping both observations in the record makes the recovery decision easier to inspect. I set the project question, system boundaries, and acceptance criteria; AI supports implementation, analysis, and checks.

What to test next—and what lies beyond

The next useful check is whether someone outside the project can use and maintain the static interface: find the relevant sources, understand unknowns and disagreements, and judge what needs updating when the information changes.

Beyond the static interface, the longer-term questions concern object identity, memory, skills, and action: how might these connect a physical object with AI?
