An AI interface for a physical object.

A drone assembly at summer camp started a larger question: how could AI reliably know the particular object it was helping someone work with?

Moonblade · Engineering prototype

Inspect the eight-input trace

Where the question began

At summer camp, I watched classmates assemble a drone while repeatedly looking up tutorials, device information, and hardware background. General-purpose AI can struggle to obtain reliable context for a particular object. I began wondering whether the object could have an interface for AI.

Step-by-step guidance alone might be less useful than a manufacturer’s existing tutorial. The harder question was how AI could know which object it was dealing with, what had changed, and which information was still reliable. Moonblade explores how an object could carry identity, knowledge, task skills, and context for compatible AI to use and pass on.

What runs today

The current software prototype implements part of this direction: a Runtime resolves evidence, checks task conditions, preserves contradictions, and records transitions. The replay below shows that mechanism in one executed software case.

Keep disagreement in the record

The important choice is visible between inputs 3 and 7: a new observation does not simply replace the previous one. The Runtime records the contradiction, retains the earlier value while conflicted, and waits for its recovery conditions to be satisfied.

That record gives the next operator something to inspect when understanding is inherited. I set the object-grounded question, system boundaries, and acceptance criteria; AI supports implementation, analysis, and checks.

The next useful check

The next useful test is a bounded physical task: change the object, check whether stale assumptions are detected, and ask another operator to recover the relevant evidence. This would connect the implemented recovery mechanism to the larger inheritance question.
